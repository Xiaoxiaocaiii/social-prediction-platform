# 社交网络分析数据字段契约

> 文档状态：T01 已完成并通过验收
> 适用范围：社交网络分析模块的内置数据适配与用户上传数据
> 更新时间：2026-10-04
> 当前实现与验收状态见[项目验收说明](验收与演示说明.md)和[实施计划](../全局关系图与社群桥接分析实施计划.md)。本文保留数据字段与降级口径契约。
> 说明：本文档只冻结数据输入契约和能力降级规则，不实现文件读取、数据库、接口或页面。

## 1. 契约目标

本契约冻结三类业务输入：

```text
users
relationships
tweets
```

契约同时区分：

1. **上传标准字段**：用户上传 CSV/JSONL 时应使用的稳定字段名；
2. **内置数据适配别名**：当前 `all_csv/merged_dataset/` 中真实存在的字段名；
3. **规范化字段**：后续 F02/F03 输出给分析模块的统一字段。

原则：

- 用户 ID 和推文 ID 始终按字符串处理；
- 不通过数值转换 ID；
- 不把缺失值转换为虚构默认值；
- 原始字段、规范化字段和计算指标分离；
- 原始文件和原始行号必须可以追溯；
- 内置数据适配不改变原始文件；
- 用户上传数据首版只在当前分析会话使用，不永久保存。

## 2. 当前真实数据盘点

已核对目录：

```text
all_csv/merged_dataset/
csv/
```

当前合并文件：

| 文件 | 观察到的真实表头 |
| --- | --- |
| `all_user_info.csv` | `用户名`、`账号ID`、`自我介绍`、`推文总数`、`关注数`、`显示名称`、`粉丝数`、`账号创建时间`、`注册地`、`source_folder` |
| `all_following_list.csv` | `source_folder`、`following_list`、`username`、`user_id` |
| `all_tweets_raw.csv` | `发布时间`、`评论数`、`书签数`、`点赞数`、`source_folder`、`转发数`、`推文原文`、`图片`、`tweet_id` |

当前已确认的适配事实：

- 用户表的稳定账号标识为 `账号ID`；
- 关系表中的 `user_id` 与 `source_folder` 表示关系发起用户；
- `following_list` 是 Python 列表字符串，例如 `['188736341', '3912832153']`；
- 推文表没有标准 `user_id`，使用 `source_folder` 关联作者；
- `source_folder` 可能是用户账号目录，也可能是 `Arab_API` 等未归属来源；
- 推文中的 `tweet_id` 已存在重复记录，需要由 F03 处理；
- 书签字段当前观察为全 0，首版不开放书签分析。

## 3. 标准文件格式

首版支持三类逻辑文件：

```text
users.csv / users.jsonl
relationships.csv / relationships.jsonl
tweets.csv / tweets.jsonl
```

### 3.1 CSV

- 必须包含首行表头；
- 字段名必须使用本契约中的标准英文名；
- 字段顺序可以不同；
- 字段名大小写必须精确匹配；
- 字段值使用 UTF-8；
- 允许 UTF-8 BOM；
- 推荐使用逗号作为分隔符；
- 不支持自动猜测分隔符；
- 不支持无表头 CSV；
- 不支持通过列序号猜测字段含义。

### 3.2 JSONL

- 每行必须是一个 JSON 对象；
- 不支持整文件 JSON 数组作为首版输入；
- 字段名必须使用标准英文名；
- 每行可独立解析；
- 非法 JSON 必须报告文件名和行号；
- 空行可以跳过并计入质量报告；
- JSON 中的 ID 仍按字符串读取；
- 不允许将数字 ID自动转换为浮点或整数。

### 3.3 编码

支持：

```text
UTF-8
UTF-8 with BOM
```

不支持：

```text
GBK / GB18030
UTF-16
本地系统编码
```

不支持的编码必须返回可理解的文件级错误，并提示转换为 UTF-8 后重新上传。

### 3.4 不支持的自由格式

首版不承诺自动适配：

- 任意字段名的 CSV；
- 无表头 CSV；
- Excel `.xlsx`；
- 数据库导出文件；
- XML；
- 多层嵌套 JSON；
- 一个文件混合 users、relationships 和 tweets；
- 仅凭文件名猜测字段；
- 仅凭中文字段含义自动推断字段；
- 使用昵称代替用户 ID；
- 使用用户名文本代替关系端点 ID；
- 将关系写成未声明语义的矩阵；
- 将推文互动写成未声明单位的自然语言。

内置数据的中文字段和聚合关注列表只属于已确认的内部适配范围，不等于开放任意中文字段自动映射。

## 4. `users` 用户文件契约

### 4.1 最小标准字段

| 标准字段名 | 中文含义 | 标准类型 | 必填 | 空值规则 | 示例 |
| --- | --- | --- | --- | --- | --- |
| `user_id` | 用户账号 ID | string | 是 | 不允许为空 | `"1002259603537702912"` |
| `username` | 用户名/账号名 | string | 否 | 允许为空，显示时回退账号 ID | `"niwcrso"` |
| `display_name` | 显示名称 | string | 否 | 允许为空，不自动补齐 | `"Narodowy Instytut Wolności"` |
| `bio` | 自我介绍 | string | 否 | 允许为空 | `""` |
| `followers_count` | 粉丝数 | integer string | 否 | 空值为未采集，不是 0 | `"1475"` |
| `following_count` | 关注数 | integer string | 否 | 空值为未采集，不是 0 | `"0"` |

### 4.2 可选扩展字段

以下字段可以保留在原始层或扩展字段中，但不属于首版最小必需字段：

| 字段名 | 中文含义 | 类型 | 空值规则 |
| --- | --- | --- | --- |
| `tweet_count` | 用户资料中的推文总数 | integer string | 空值为未采集 |
| `created_at` | 账号创建时间 | datetime string | 无法解析时标记异常 |
| `location` | 注册地/位置 | string | 允许为空 |
| `source_folder` | 原始来源目录 | string | 内置数据可用，上传可选 |

### 4.3 `users` 字段规则

#### `user_id`

- 必填；
- 按字符串处理；
- 保留前导零；
- 不允许用用户名代替；
- 不允许转换为 Java `Long` 或 JavaScript `Number`；
- 空值、数组、对象、浮点格式均视为非法；
- 同一文件内重复 `user_id` 进入质量报告；
- 规范化后以字符串作为用户主键。

#### `username`

- 可选；
- 不作为主键；
- 空值时页面显示账号 ID或“用户名未采集”；
- 不根据简介、显示名称或推文推断用户名；
- 同名不视为同一用户。

#### `display_name`

- 可选；
- 允许为空；
- 不作为关系关联键；
- 不把显示名称当作唯一身份。

#### `bio`

- 可选；
- 保留原文；
- 允许换行；
- 不从简介推导主题、立场或身份结论。

#### `followers_count` / `following_count`

- 逻辑上为非负整数；
- 上传文件建议使用十进制数字字符串；
- 空值表示未采集；
- 明确 `0` 表示采集到的零值；
- 负数、小数、带单位文本视为异常；
- 静态字段不解释为增长量或活跃度。

### 4.4 内置字段适配

| 内置字段 | 规范化字段 | 适配说明 |
| --- | --- | --- |
| `账号ID` | `user_id` | 直接字符串化 |
| `用户名` | `username` | 空值保留 |
| `显示名称` | `display_name` | 空值保留 |
| `自我介绍` | `bio` | 原文保留 |
| `粉丝数` | `followers_count` | 数字字符串校验 |
| `关注数` | `following_count` | 数字字符串校验 |
| `推文总数` | `tweet_count` | 只作为原始账户字段 |
| `账号创建时间` | `created_at` | 时间解析失败需报告 |
| `注册地` | `location` | 只作为原始账户字段 |
| `source_folder` | `source_folder` | 追溯字段，不作为首选主键 |

用户主键优先级：

```text
明确账号 ID（账号ID/user_id）
→ 关注列表中的 user_id
→ 推文中的 source_folder
```

## 5. `relationships` 关系文件契约

### 5.1 标准最小字段

| 标准字段名 | 中文含义 | 标准类型 | 必填 | 空值规则 | 示例 |
| --- | --- | --- | --- | --- | --- |
| `source_user_id` | 关注发起方 | string | 是 | 不允许为空 | `"1002259603537702912"` |
| `target_user_id` | 被关注方 | string | 是 | 不允许为空 | `"188736341"` |

### 5.2 关系方向

唯一关系方向：

```text
source_user_id → target_user_id
```

含义：

```text
source_user_id 关注 target_user_id
```

因此：

- source 节点是关注者；
- target 节点是被关注者；
- target 的入度表示收到的关注关系数量；
- source 的出度表示发出的关注关系数量；
- 不允许在页面或计算中反转方向；
- 不根据“粉丝数”字段推断关系方向。

### 5.3 关系数据规则

- 两个端点均按字符串处理；
- 空端点为非法关系；
- 自环是否保留由 T03 规范化规则处理，但原始记录必须保留并报告；
- 重复关系原始层保留，分析层去重；
- target 不在 users 中时保留为外部节点；
- 外部节点可以参与网络计算；
- 外部节点默认不进入用户资料排行；
- 关系行必须保留原始文件和行号；
- 不允许用用户名、显示名称或目录名称替代端点 ID。

### 5.4 内置聚合关系适配

当前内置 `all_following_list.csv` 不是标准边表，而是每个 source 用户一行：

```text
source_folder,following_list,username,user_id
```

适配规则：

1. `user_id` 或明确账号 ID作为 `source_user_id`；
2. 解析 `following_list` Python 列表字符串；
3. 列表中的每个元素生成一条 `source_user_id → target_user_id`；
4. 空列表生成 0 条边；
5. 非法列表行进入文件/行质量报告；
6. 不把 `username` 作为 target ID；
7. 保留原始聚合行和生成边的来源关系。

内置适配不代表上传用户可以提交任意 `following_list` 文件。用户上传关系文件首选标准边表。

## 6. `tweets` 推文文件契约

### 6.1 标准最小字段

| 标准字段名 | 中文含义 | 标准类型 | 必填 | 空值规则 | 示例 |
| --- | --- | --- | --- | --- | --- |
| `tweet_id` | 推文 ID | string | 是 | 不允许为空 | `"1997991551738183929"` |
| `user_id` | 推文作者 ID | string | 是 | 不允许为空 | `"1002259603537702912"` |
| `created_at` | 发布时间 | datetime string | 是 | 空值或无法解析需报告 | `"2025-12-08"` |
| `text` | 推文原文 | string | 是 | 空文本进入质量报告 | `"原文..."` |
| `like_count` | 点赞数 | integer string | 否 | 空值表示未采集 | `"3"` |
| `reply_count` | 评论数 | integer string | 否 | 空值表示未采集 | `"0"` |
| `repost_count` | 转发数 | integer string | 否 | 空值表示未采集 | `"0"` |
| `bookmark_count` | 书签数 | integer string | 否 | 空值表示未采集 | `"0"` |

### 6.2 `tweets` 字段规则

#### `tweet_id`

- 必填；
- 按字符串处理；
- 不允许转换为数值；
- 原始层允许重复；
- 分析层按 `tweet_id` 去重；
- 内容冲突的重复 ID 必须标记；
- 不以行号代替 tweet ID。

#### `user_id`

- 必填；
- 表示推文作者；
- 必须与 users 的 `user_id` 或可识别外部节点关联；
- 不能使用显示名称或用户名替代；
- 无法关联时进入未归属或未关联质量状态；
- 未归属来源不默认进入用户排行和用户详情。

#### `created_at`

- 逻辑上必填；
- 推荐使用 ISO 日期或 ISO 8601 日期时间；
- 无法解析时保留原始值并报告；
- 无法解析的记录不进入时间分布，但可以保留在原始推文列表；
- 不根据文件夹名称推断发布时间。

#### `text`

- 逻辑上必填；
- 原文保留；
- 换行、URL、提及、标签和原始语言不在字段契约阶段删除；
- F06 另行生成分析文本；
- 空文本可以保留，但不进入有效文本分析样本；
- 不根据文本自动补写作者或主题。

#### 互动字段

```text
like_count
reply_count
repost_count
bookmark_count
```

统一规则：

- 逻辑上为非负整数；
- 空值表示未采集或无法关联；
- 明确 `0` 表示采集到的零值；
- 负数、小数、带单位文本视为异常；
- 点赞、评论、转发分开统计；
- 不在字段契约阶段创建综合分；
- 书签字段保留，但当前内置数据全为 0 时能力状态为 `disabled`。

### 6.3 内置字段适配

| 内置字段 | 规范化字段 | 适配说明 |
| --- | --- | --- |
| `tweet_id` | `tweet_id` | 直接字符串化 |
| `source_folder` | `user_id` 或未归属来源 | 先按用户主键关联，无法关联时隔离 |
| `发布时间` | `created_at` | 保留原始值并解析 |
| `推文原文` | `text` | 原文保留 |
| `点赞数` | `like_count` | 非负整数校验 |
| `评论数` | `reply_count` | 非负整数校验 |
| `转发数` | `repost_count` | 非负整数校验 |
| `书签数` | `bookmark_count` | 全零时 disabled |
| `图片` | `media_raw` | 非最小字段，原始层可保留 |

### 6.4 `source_folder` 关联规则

内置推文的 `source_folder` 是当前作者关联来源，不直接等价于标准上传字段 `user_id`。

关联优先级：

```text
source_folder 与用户账号 ID明确匹配
→ 关注列表中的 user_id 可匹配
→ 保留为外部/未归属来源
```

特殊来源：

```text
Arab_API
```

处理为：

- `source_type = unassigned_source`；
- 保留原始推文；
- 进入质量报告；
- 可出现在全局推文结果；
- 默认不进入用户聚合排行；
- 默认不进入 B05 用户详情；
- 默认不进入 B07 主题用户网络。

## 7. 字段类型和空值统一规则

### 7.1 ID 字段

字段：

```text
user_id
source_user_id
target_user_id
tweet_id
source_folder
```

规则：

- 统一为字符串；
- 去除首尾空白，但不改变中间内容；
- 不做数值化；
- 不做科学计数法转换；
- 不把 `null`、空字符串和 `"0"` 混为一类；
- `"0"` 只有在原始数据明确为 ID 时才作为字符串保留；
- 缺失 ID 进入错误或严重质量问题。

### 7.2 计数字段

字段：

```text
followers_count
following_count
tweet_count
like_count
reply_count
repost_count
bookmark_count
```

规则：

| 输入 | 规范化状态 | 页面表达 |
| --- | --- | --- |
| 空值 | missing | 未采集/无法关联 |
| `"0"` | valid_zero | `0` |
| 正整数 | valid | 原始数值 |
| 负数 | invalid | 数据异常 |
| 小数 | invalid | 数据异常 |
| 文本单位 | invalid | 数据异常 |

### 7.3 时间字段

- 保留原始值；
- 解析为统一时间对象供计算；
- 解析失败不修改原文；
- 解析失败记录行号；
- 无法解析记录不进入时间聚合；
- 不用默认日期补齐。

### 7.4 文本字段

- 原文和分析文本分开；
- 原文空值不补写；
- 原文不在 F02/F03 阶段清洗覆盖；
- F06 负责分析文本的清洗和语言处理；
- 文本分析失败不删除原始推文。

## 8. 文件组合和能力矩阵

能力状态：

```text
available
limited
disabled
unavailable
checking
```

### 8.1 仅 `relationships`

可开放：

- B01 数据集入口；
- B02 网络规模和关系摘要；
- B03 用户关注网络；
- B04 入度、出度、PageRank；
- 网络密度和孤立节点。

降级：

- B04 原始账户字段排行为 `unavailable`；
- B05 用户资料为 `limited` 或 `unavailable`；
- B06 推文互动为 `unavailable`；
- B07 文本主题为 `unavailable`。

### 8.2 `relationships + users`

可开放：

- 关系网络；
- 用户资料；
- 外部节点；
- 入度、出度、PageRank；
- 用户账户字段；
- B04 原始字段排行；
- B05 用户详情基础区。

降级：

- B06 推文互动为 `unavailable`；
- B07 主题分析为 `unavailable`；
- B05 推文和文本区块为 `unavailable`。

### 8.3 `relationships + tweets`

可开放：

- 网络结构；
- 推文作者关联；
- 点赞、评论、转发统计；
- B06 推文互动；
- B07 关键词和 TF-IDF，前提是 `text` 有效；
- 相关作者的有限详情。

降级：

- B04 用户资料排行为 `limited`；
- B05 资料区为 `limited`；
- 无法关联作者的推文保留为未归属来源；
- B07 主题用户网络只使用已关联作者。

### 8.4 `users + tweets`，无 `relationships`

可开放：

- B01 数据集入口；
- B05 用户和推文详情；
- B06 推文与互动；
- B07 文本主题和相关用户。

禁用或不可用：

- B02 网络结构指标为 `unavailable`；
- B03 用户关注网络为 `unavailable`；
- B04 入度、出度、PageRank 为 `unavailable`；
- B07 真实关注子图为 `disabled`。

### 8.5 三类文件完整

可开放：

- B01-B07 主要能力；
- 受质量报告和字段状态限制的局部降级；
- 书签字段当前全零时保持 `disabled`；
- 外部节点和未归属来源按规则隔离。

### 8.6 文件组合判定原则

- 能力由 S02 统一判定；
- 业务页面不自行猜测；
- 缺少字段优先显示 `limited` 或 `unavailable`；
- 全零书签显示 `disabled`，不是 `available`；
- 文件存在但有效样本为零时按质量状态降级；
- 文件读取失败不能被当作空文件；
- 文件存在、字段存在、有效样本存在是三个独立检查层。

## 9. 统一文件模板

### 9.1 `users.csv`

```csv
user_id,username,display_name,bio,followers_count,following_count
1002259603537702912,niwcrso,Narodowy Instytut Wolności,,1475,0
100271646,IDEASPERU,Empresa,,,0
```

说明：

- `user_id` 必填；
- 计数字段为空表示未采集；
- `0` 表示明确零值；
- 不在模板中要求 `source_folder`。

### 9.2 `relationships.csv`

```csv
source_user_id,target_user_id
1002259603537702912,188736341
1002259603537702912,3912832153
```

说明：

- 每行一条有向关系；
- source 关注 target；
- 不使用用户名；
- 不使用 Python 列表字符串作为上传标准格式。

### 9.3 `tweets.csv`

```csv
tweet_id,user_id,created_at,text,like_count,reply_count,repost_count,bookmark_count
1997991551738183929,1002259603537702912,2025-12-08,"原文...",3,0,0,0
```

说明：

- `tweet_id`、`user_id`、`created_at`、`text` 为首版逻辑必填；
- 互动字段可以为空；
- 原文中的逗号、换行和引号必须遵守 CSV 转义；
- 书签字段保留，但当前无有效差异时不开放分析。

### 9.4 JSONL 示例

```json
{"user_id":"1002259603537702912","username":"niwcrso","display_name":"Narodowy Instytut Wolności","bio":"","followers_count":"1475","following_count":"0"}
```

```json
{"source_user_id":"1002259603537702912","target_user_id":"188736341"}
```

```json
{"tweet_id":"1997991551738183929","user_id":"1002259603537702912","created_at":"2025-12-08","text":"原文...","like_count":"3","reply_count":"0","repost_count":"0","bookmark_count":"0"}
```

JSONL 中推荐将 ID 和计数字段写为字符串，以避免 ID 精度损失和跨语言解析差异；实现层必须对字段类型执行契约校验。

## 10. 字段映射和错误等级

### 10.1 错误等级

| 等级 | 含义 | 示例 | 能力影响 |
| --- | --- | --- | --- |
| blocking | 文件无法作为该类数据使用 | 无表头、格式完全错误 | 该文件 unavailable |
| error | 必填字段或关键行非法 | 缺失 user_id | 相关记录拒绝进入分析 |
| warning | 可保留但影响部分能力 | 作者无法关联 | limited，隔离未归属 |
| info | 不影响核心计算 | 可选 bio 为空 | 仅提示 |

### 10.2 字段缺失

- 缺少标准必填字段：文件级 `blocking`；
- 必填字段部分行为空：行级 `error`；
- 可选字段缺失：`info`，对应能力不自动关闭；
- 关键计算字段整体缺失：相关能力 `unavailable`；
- 字段存在但有效值为零：不能按字段缺失处理。

### 10.3 字段别名

只允许当前已核对的内置别名：

```text
账号ID → user_id
用户名 → username
显示名称 → display_name
自我介绍 → bio
粉丝数 → followers_count
关注数 → following_count
推文总数 → tweet_count
账号创建时间 → created_at
注册地 → location
发布时间 → created_at
评论数 → reply_count
书签数 → bookmark_count
点赞数 → like_count
转发数 → repost_count
推文原文 → text
```

`source_folder` 不作为通用字段别名自动映射，只有内置数据适配层按已确认规则处理。

## 11. 原始层、规范化层和分析层

### 11.1 原始层

保留：

- 原文件名；
- 原行号；
- 原字段名；
- 原字段值；
- 原始编码；
- 原始记录；
- 重复记录；
- 非法记录摘要。

### 11.2 规范化层

输出：

- 标准字段名；
- 字符串 ID；
- 规范化关系边；
- 关联状态；
- 外部节点状态；
- 未归属来源状态；
- 去重标识；
- 解析状态；
- 来源文件和行号。

### 11.3 分析层

只消费：

- 通过规范化校验的记录；
- 明确的有效关系；
- 按 `tweet_id` 去重后的推文；
- 已标记状态的用户和外部节点；
- 有效时间和互动字段；
- 有效文本样本。

禁止：

- 业务模块直接读取原始文件；
- 业务模块绕过 F02/F03 自行映射字段；
- 业务模块自行删除异常；
- 业务模块自行重新定义空值和零值。
