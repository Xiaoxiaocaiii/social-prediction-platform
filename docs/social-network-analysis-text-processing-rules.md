## 1. 首版边界

首版文本分析只提供：

- 文本清洗；
- 中文、英文和混合文本识别；
- 关键词频次统计；
- TF-IDF 区分度计算；
- 按关键词匹配推文；
- 主题相关推文和作者汇总；
- 文本结果与真实关注关系子图联动。

首版明确不提供：

- 大型语言模型；
- 语义向量；
- 复杂语义聚类；
- 自动主题命名；
- 情感、立场、意图判断；
- 实体消歧；
- 传播路径推导；
- 因果关系推断；
- 用户社会影响力判断。

## 2. 文本字段分层

### 2.1 原文层

字段：

```text
text_original
```

规则：

- 保留原始推文文本；
- 不覆盖；
- 不因清洗失败而删除；
- 详情和导出默认使用原文；
- 原始文本与 `tweet_id` 绑定；
- 空原文保留并标记质量状态。

### 2.2 规范化文本层

字段：

```text
text_normalized
```

用途：

- 统一 Unicode 表示；
- 规范空白；
- 规范全角/半角；
- 统一大小写规则；
- 识别 URL、提及、标签和表情边界；
- 供后续分词和匹配使用。

`text_normalized` 不得替代 `text_original` 展示。

### 2.3 分析词元层

字段：

```text
tokens
tokens_language
tokens_filtered
```

用途：

- 关键词统计；
- TF-IDF；
- 主题匹配；
- 结果回溯。

每个词元必须能回溯到：

```text
tweet_id
source_file
source_row_number
text_processing_version
```

### 2.4 处理状态

```text
text_available
text_empty
text_normalized
text_tokenized
text_language_unknown
text_processing_failed
```

## 3. 文本处理流水线

固定顺序：

```text
读取原文
→ 保存 text_original
→ Unicode 规范化
→ 空白规范化
→ URL/提及/标签识别
→ 语言识别
→ 语言分词
→ 停用词过滤
→ 低信息词过滤
→ 生成 tokens_filtered
→ 关键词统计
→ TF-IDF 计算
→ 主题匹配
```

任何步骤失败：

- 原文仍保留；
- 当前文本记录标记失败原因；
- 不使用清洗后的半成品冒充完整分析结果；
- 其他推文继续处理；
- 质量报告统计失败数量；
- B07 能力按 S02 结果降级。

## 4. Unicode 和空白规范化

### 4.1 Unicode

- 使用统一 Unicode 规范化形式；
- 中文、英文、数字保留；
- 全角英数字转换为半角；
- 全角标点按规则映射为标准标点；
- 不删除原始字符；
- 不对 ID、URL 和原文做不可逆覆盖。

### 4.2 空白

- 连续空格合并为一个分析分隔符；
- 首尾空白去除；
- 换行、制表符统一为空白；
- 原文换行不在 `text_original` 中修改；
- 空白文本规范化后仍为空时标记 `text_empty`。

### 4.3 大小写

- 英文词元统一转小写用于匹配和统计；
- 原文大小写保留；
- 中文不做大小写转换；
- 用户输入英文主题同样转小写；
- 大小写差异不产生两个英文词元。

## 5. URL、提及、标签和标点

### 5.1 URL

URL 在分析文本中：

- 不作为关键词词元；
- 从 `tokens_filtered` 排除；
- 统计 `url_count`；
- 原文保留；
- 若主题查询为完整 URL，可使用单独的 URL 精确匹配，不进入普通词频；
- URL 处理状态写入文本质量信息。

### 5.2 用户提及

如：

```text
@username
```

规则：

- `@` 和用户名默认不作为普通主题词；
- 统计 `mention_count`；
- 原文保留；
- 不根据提及文本推断用户关系；
- 不将提及自动加入主题相关用户；
- 如果提及对应关系数据中的用户，只能作为原始文本证据展示，不能替代真实关注边。

### 5.3 Hashtag

如：

```text
#人工智能
#ClimateChange
```

规则：

- 去除 `#` 符号；
- 保留标签正文作为候选词；
- 英文标签转小写；
- 中文标签按中文分词规则处理；
- 同时记录 `hashtag_count`；
- 标签可以参与关键词统计和 TF-IDF；
- 标签不自动代表主题结论；
- 标签匹配结果必须回溯推文 ID。

### 5.4 标点和符号

- 普通标点不作为词元；
- 连字符在英文复合词中保留一次规范化形式；
- 连续感叹号、问号不作为主题词；
- 货币、百分号和数字单位保留为结构信息，但默认不进入普通关键词；
- 表情默认不进入关键词和 TF-IDF；
- 原文中的标点和表情保留；
- 标点处理规则必须随版本变化记录。

## 6. 语言状态

### 6.1 语言分类

每条有效文本至少标记一种状态：

```text
zh
en
mixed
other
unknown
```

含义：

| 状态 | 含义 |
| --- | --- |
| `zh` | 主要内容为中文 |
| `en` | 主要内容为英文 |
| `mixed` | 中文和英文均达到有效文本阈值 |
| `other` | 主要内容为其他语言或脚本 |
| `unknown` | 有效字符不足以识别 |

### 6.2 判断原则

- URL、提及、数字和标点不作为主要语言判断依据；
- 中文字符与英文字母分别计数；
- 中英文均达到最小有效字符数时标记 `mixed`；
- 只有少量中文或英文嵌入其他文本时，不强行标记为对应语言；
- 不将 `other` 自动翻译为中文或英文；
- 无法识别的文本保留原文并标记 `unknown`。

### 6.3 语言统计

质量报告和 B07 摘要至少展示：

```text
中文文本数
英文文本数
混合文本数
其他语言数
未知语言数
有效文本数
```

## 7. 中文分词

### 7.1 首版规则

- 使用版本化中文词典进行最大匹配；
- 保留中文词语作为词元；
- 未命中词典的连续中文片段按最小可用片段切分；
- 单个常见功能字由中文停用词表过滤；
- 用户输入的中文短语按同一规则处理；
- 词典版本写入文本处理元信息。

### 7.2 中文词元限制

- 纯标点不生成词元；
- 纯数字默认不生成普通关键词；
- 单个汉字只有在查询词或固定领域词典中出现时才可保留；
- 词元长度、字符范围和词典版本必须可复现；
- 不使用模型生成同义词或语义扩展。

## 8. 英文分词

### 8.1 规范化

- 转小写；
- 按空白、标点和符号切分；
- 保留合法字母序列；
- 保留英文复合词的规范化形式；
- URL、提及和表情按前述规则处理；
- 英文缩写不自动展开。

### 8.2 词形处理

首版不进行复杂词形还原和语义归并。

可以进行的基础处理：

- 去除首尾无意义符号；
- 统一大小写；
- 按固定规则处理简单复数后缀。

以下内容不自动执行：

- 同义词合并；
- 词义消歧；
- 机器翻译；
- 语义扩展；
- 上下文推理。

## 9. 混合文本

### 9.1 处理方式

混合文本使用分语言流水线：

```text
中文片段 → 中文分词和中文停用词
英文片段 → 英文分词和英文停用词
数字/符号 → 结构识别
```

最终词元保留语言标记：

```text
token
token_language
```

### 9.2 统计展示

B07 可以切换：

- 全部语言混合统计；
- 中文词元；
- 英文词元；
- 混合文本样本。

切换时必须显示当前语言范围，不得把中英文词频静默合并为同一词。

## 10. 停用词表

### 10.1 管理方式

停用词表按语言和版本管理：

```text
stopwords_zh
stopwords_en
stopwords_other
stopwords_version
```

首版固定：

```text
stopwords_version: stopwords-v1.0
```

### 10.2 表内容

中文停用词表覆盖：

- 常见虚词；
- 代词；
- 常见功能词；
- 无主题区分度的高频词。

英文停用词表覆盖：

- 常见冠词；
- 常见介词；
- 常见代词；
- 常见助动词；
- 无主题区分度的高频词。

### 10.3 规则

- 停用词只影响分析词元；
- 原文不删除；
- 停用词表不影响 tweet_id、作者 ID、来源和互动字段；
- 用户可以查看当前停用词版本；
- 停用词更新必须升级文本处理版本；
- 主题输入词如果命中停用词，显示“该词缺少有效区分度”；
- 不因停用词匹配而删除整条推文。

## 11. 低信息词和样本过滤

分析层默认过滤：

- 空字符串；
- 纯标点；
- 纯 URL；
- 纯提及；
- 纯表情；
- 仅由停用词组成的文本；
- 不满足最小有效字符数的文本。

这些记录：

- 原文保留；
- 计入文本质量报告；
- 不进入关键词和 TF-IDF 有效样本；
- 不影响推文原文列表的展示。

## 12. 关键词统计

### 12.1 统计单位

关键词统计的基础文档单位是：

```text
一条去重后的有效推文
```

同一推文中的同一词元：

- 频次统计可计数多次；
- 推文覆盖数只计 1 条；
- 用户覆盖数只计 1 个关联作者；
- 不因重复推文重复计入。

### 12.2 输出字段

```text
term
language
term_frequency
document_frequency
user_frequency
sample_count
first_seen_at
last_seen_at
text_processing_version
```

### 12.3 排序

默认排序：

1. `term_frequency` 降序；
2. `document_frequency` 降序；
3. 词元字符串升序。

页面必须同时显示：

- 原始频次；
- 覆盖推文数；
- 覆盖用户数；
- 语言；
- 当前样本范围。

### 12.4 解释边界

关键词频次表示：

> 当前有效文本样本中某个词元出现的次数。

不得解释为：

- 主题重要性；
- 用户立场；
- 传播强度；
- 社会影响力；
- 因果关系。

## 13. TF-IDF

### 13.1 文档单位

TF-IDF 的文档单位固定为：

```text
一条去重后的有效推文
```

不是：

- 用户；
- 关系边；
- 时间窗口；
- 原始文件；
- 主题相关用户集合。

### 13.2 词频

对于词元 `t` 和推文文档 `d`：

```text
raw_tf(t, d) = t 在 d 中出现的次数
```

采用对数词频：

```text
tf(t, d) = 1 + log(raw_tf(t, d)), raw_tf(t, d) > 0
tf(t, d) = 0, raw_tf(t, d) = 0
```

### 13.3 逆文档频率

设：

```text
N = 有效推文文档总数
df(t) = 包含 t 的有效推文数
```

采用平滑逆文档频率：

```text
idf(t) = log((N + 1) / (df(t) + 1)) + 1
```

### 13.4 TF-IDF 分数

```text
tfidf(t, d) = tf(t, d) × idf(t)
```

首版不进行向量归一化，除非后续任务明确升级版本并重新确认。

### 13.5 排序

默认：

1. TF-IDF 分数降序；
2. 文档频次降序；
3. 词元字符串升序；
4. `tweet_id` 字符串升序作为稳定排序。

### 13.6 解释边界

TF-IDF 只表示：

> 某个词元相对于当前推文样本集合的区分度。

不得解释为：

- 词元的重要性；
- 主题因果因素；
- 用户立场；
- 传播路径；
- 社会影响力；
- 真实世界事件影响。

## 14. 主题匹配

### 14.1 主题输入

支持：

- 单个中文关键词；
- 单个英文关键词；
- 中英文混合关键词；
- 简短主题短语；
- Hashtag 形式输入。

不支持：

- 长篇问题；
- 自动意图理解；
- 复杂语义推理；
- 自然语言主题改写；
- LLM 生成扩展词。

### 14.2 输入规范化

用户输入使用和推文相同的规则：

```text
Unicode 规范化
→ 空白规范化
→ 语言识别
→ 同语言分词
→ 停用词过滤
```

如果输入为空或全部为停用词：

- 不执行查询；
- 显示明确提示；
- 不自动改写用户输入。

### 14.3 精确词元匹配

主题相关推文首先按规范化词元匹配：

- 单词匹配按完整词元；
- 中文短语按连续词元序列；
- 英文匹配不区分大小写；
- 标签正文按去除 `#` 后的词元匹配；
- 不默认进行同义词扩展；
- 不默认进行模糊拼写纠正；
- 不把提及用户名当作主题词。

### 14.4 TF-IDF 排序

关键词匹配得到候选推文后：

- 使用查询词元的 TF-IDF 分数进行相关度排序；
- 多个查询词元的分数求和；
- 没有 TF-IDF 分数但存在精确匹配的推文仍可展示；
- 页面区分“关键词命中”和“TF-IDF 区分度”；
- 排序结果必须保留 `tweet_id`。

主题匹配分数：

```text
topic_score(d, Q) = Σ tfidf(t, d), t ∈ Q 且 t 出现在 d
```

没有匹配词元时：

```text
topic_score = 0
```

### 14.5 结果字段

每条匹配推文至少返回：

```text
tweet_id
author_id
matched_terms
match_type
topic_score
text_processing_version
dataset_version
```

`match_type` 可为：

```text
keyword_exact
hashtag_exact
keyword_and_tfidf
```

### 14.6 无结果

无匹配结果时：

```text
当前文本样本中没有找到与该主题完全匹配的推文。
```

不得：

- 自动推荐未经计算的相近主题；
- 自动生成主题结论；
- 用用户提及或关系邻居制造匹配；
- 把无结果解释为“该主题不存在”。

## 15. 主题相关用户

主题相关用户只能由：

```text
主题匹配推文
→ 已关联作者
→ 用户去重汇总
```

得到。

规则：

- `unassigned_source` 推文不生成相关用户；
- 作者资料缺失时保留作者 ID和“资料未采集”状态；
- 同一用户的匹配推文只去重计数；
- 主题互动总量、均值和样本量与 B06 口径一致；
- 不生成综合主题影响力分；
- 不把相关用户排序称为主题意见领袖。

## 16. 主题与真实网络联动

B07 的关系子图只能使用：

```text
主题相关用户
→ T04 规范化真实关注关系
→ 局部有向子图
```

规则：

- 主题共现不生成虚构边；
- 关键词共同出现不视为传播路径；
- 提及不替代关注关系；
- 关系网络使用 T04 的指标版本；
- 外部节点保留并标记；
- 超过 100 节点或 500 边时提示缩小范围；
- 主题相关用户不足时显示样本不足；
- 不把主题网络图解释为主题传播网络。

统一边界文案：

> 主题相关用户网络仅表示当前数据中已记录的真实关注关系，不表示主题传播路径、用户立场或因果关系。

## 17. 文本版本

首版固定：

```text
text_processing_version: text-processing-v1.0
stopwords_version: stopwords-v1.0
tokenizer_version: tokenizer-v1.0
tfidf_version: tfidf-v1.0
```

以下变化必须升级版本：

- Unicode 或空白处理；
- URL、提及、标签规则；
- 中文词典；
- 英文分词；
- 停用词表；
- 语言识别阈值；
- TF-IDF 公式；
- 主题匹配规则；
- 词元过滤规则。

## 19. 状态和降级

| 情况 | 文本能力状态 | 处理 |
| --- | --- | --- |
| 有效文本充分 | available | 开放关键词和 TF-IDF |
| 文本部分缺失 | limited | 开放并提示样本量 |
| 只有少量有效文本 | limited | 显示稳定性提示 |
| 全部文本为空 | unavailable | 关闭文本分析并说明原因 |
| 词元生成失败 | limited/unavailable | 保留原文，显示失败数量 |
| 只有 URL/提及 | limited | 不进入关键词统计 |
| 主题无匹配 | empty | 保留查询，显示无结果 |
| 书签全零 | 不影响文本 | B06 书签单独 disabled |
