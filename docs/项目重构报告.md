# 多模态社交媒体流行度预测与可视化分析平台（重构版）项目报告

> 文档版本：v2.0 ｜ 日期：2026-08-11 ｜ 提交对象：项目负责人

## 一、背景与目标

原版平台存在核心问题：检索、预测、建议三个功能为写死的 mock 数据，AI 配图依赖外部 API 且效果不佳，整体无法支撑答辩演示，也不符合申报书「真实数据 + 方法创新」的定位。

本次对平台进行整体重构，确立三条原则：

1. **全部真实数据**：页面展示、检索、预测全部基于 28 万条真实数据计算，不做假数据；
2. **诚实标注**：模型未接入前，预测明确标注「基线预测」，不伪装成模型结果；
3. **模型后接入**：接口契约先行，模型团队交付后通过配置切换，前端零改动。

## 二、系统概要

### 技术栈

| 层次 | 选型 |
| --- | --- |
| 后端 | Java 17 + Spring Boot 3.2.5 + Maven + SQLite（sqlite-jdbc，FTS5 全文检索） |
| 前端 | 静态 HTML/CSS/JS + ECharts 5.5.1（全部本地化，断网可用） |
| 数据处理 | Python 脚本（csv → SQLite 索引、封面提取、分卷还原） |
| 测试 | JUnit 5 + MockMvc（24 个用例） |

### 架构

```text
前端（4 个页面，本地静态资源）
        │ HTTP
Java Spring Boot 网关（REST API + SQLite 查询 + BM25 基线预测）
        │ SQLite 索引（282,481 行）+ 本地封面（data/covers/）
```

## 三、数据资产

数据来源为 SMTPD 数据集：28 万条真实 YouTube 视频（封面图 + 文本 + 30 天热度序列）。

| 资产 | 说明 |
| --- | --- |
| `data/basic_view_pn.csv` | 原始数据 608MB（282,481 行，35 列） |
| `data/smtpd.db` | SQLite 索引 1.89GB（15 个分类，FTS5 trigram 中文全文索引） |
| `data/img_yt.zip` | 封面压缩包 9.25GB（201,408 个条目，由分卷还原） |
| `data/covers/` | 本地封面 19,732 张（轻量方案，缺失时按需从 zip 补提） |

## 四、功能清单

### 页面（4 个）

1. **上传预测**：拖拽/选择图片 + 文案输入 → 检索最相似的历史视频作为参考案例 → 输出 30 天预测曲线（标注「基线预测：参考案例真实曲线平均」），图表含峰值标注、悬浮数值；
2. **热度排行榜**：榜单切换（全站 / 15 个分类 × Day30 总榜 / Day1 新热榜 / 长红榜），支持查找视频、分页；点开视频查看详情弹窗（真实 30 天曲线、峰值天、衰减率）；
3. **数据洞察**：分类平均热度柱状图、Day1-Day30 相关性散点图（r = 0.9296）、平均热度衰减曲线（整体 / 分类切换）；统计结果内存缓存，首开后秒开；
4. **曲线对比**：任选 2~3 个视频叠加真实曲线，展示峰值天、衰减率、Day30 指标表，含预置示例。

### 接口（统一返回 `{code, message, data}`）

| 接口 | 说明 |
| --- | --- |
| `GET /api/health` | 健康检查 |
| `GET /api/videos` | 分页 / 榜单范围（分类）/ 榜单口径（day30 / day1 / longrun）/ 查找 |
| `GET /api/videos/{id}` | 视频详情 + 30 天曲线 + 峰值/衰减指标 |
| `GET /api/insights` | 分类热度、Day1-Day30 相关性、平均衰减曲线（支持 `?refresh=true` 重算） |
| `POST /api/compare` | 2~3 个视频曲线对比 |
| `POST /api/predict` | 上传图文 + 30 天基线预测（multipart） |
| `GET /covers/{前缀}/{id}.jpg` | 封面（缺失按需提取 / 占位图） |

## 六、模型接入说明（模型团队关注）

### 预测服务

预测服务为双实现，由配置切换：

- `app.prediction-mode=baseline`（默认）：BM25 检索参考案例，取真实曲线平均，纯数据计算；
- `app.prediction-mode=remote`：HTTP 调用 Python 模型服务。

Python 服务契约：

```text
POST http://127.0.0.1:5001/predict
入参: { "text": "...", "imagePath": "...", "topK": 5 }
出参: { "prediction": [30 个数值], "references": [{ videoId, title, coverPath, userId, day30, score }] }
```

模型团队按契约实现后，改一个配置即可切换，前端与接口零改动。

### 生成增强

扩散模型已确认为 `flax/stable-diffusion-2-1`。处理方式：模型团队离线生成「语义补充图」样例，用于论文与答辩材料；平台预留 `POST /api/generate` 契约，出图效果达标后再评估是否交互化。

## 七、测试与验证

- 自动化测试：24 项 JUnit / MockMvc 用例全部通过；
- 真实 HTTP 冒烟：7 个接口全部验证通过（含上传、预测、封面按需补提）；
- 浏览器走查：四页面全流程通过（无头 Edge + Playwright）；
- 断网模拟：屏蔽外部网络后四页面仍可完整使用（仅详情页头像为外部资源，自动降级占位图）；
- 关键性能：数据洞察统计缓存后 3.8 秒 → 7 毫秒；中文全文检索 15 毫秒；滚动性能修复后最大帧间隔 25.1ms → 9.2ms。

## 八、最终版视觉与体验升级（2026-08-11）

- **双主题**：深色霓虹 / 浅色精致，顶栏图标一键切换，图表实时重绘，选择持久化到 localStorage；
- **动效体系**：预加载动画、背景粒子与极光光斑、滚动进度条、磁吸按钮、卡片 3D 倾斜、图表入场生长动画、滚动揭示；
- **细节打磨**：图表内陷面板、卡片顶部高光线、封面相框感、按钮按压缩放、数字等宽排版、统计单位后缀、顶栏滚动收缩、页脚数据行；
- **滚动性能**：移除 fixed 背景与顶栏 backdrop-filter，极光降模糊并去除透明度动画，滚动期间自动暂停重特效。

## 十、已知边界与后续事项

1. 参考案例目前为词面匹配（BM25），跨语言与语义相似度有限；已确认暂不优化，作为基线展示真实数据；
2. 生成增强未交互化，以离线样例 + 静态展示呈现；
3. 封面为轻量方案（19,732 张常用），其余按需补提；答辩前可选用做一次全量补提后删除 `img_yt.zip` 释放约 9GB；
4. 数据洞察首次加载需统计 28 万条数据（约 3~5 秒），结果已缓存，后续秒开。
