> 文档状态：已完成复盘并存档
> 复盘范围：B01-B07 业务功能模块及其 F07/F08 承载约束
> 更新时间：2026-11-12（补充现状说明）
> 关联文档：[实施计划与验收记录](../全局关系图与社群桥接分析实施计划.md)
>
> 本文主体是 2026-10-04 的业务模块设计复盘，其中“首版明确不包含社区发现”“上传只支持基础分析”等内容属于当时的规划基线，不代表当前实现状态。全局图、Louvain/Clique、跨社群候选和上传分析后续已完成；当前交付范围以 README 与实施计划为准。本文的模块职责和数据解释边界仍可作为历史业务设计参考。

## 1. 复盘目的

本次复盘用于确认 B01-B07 是否形成完整业务链路，并检查：

- 模块职责是否清晰；
- 模块之间是否存在重复；
- 前后置依赖是否合理；
- 用户是否可以从数据集入口走到完整分析结果；
- 每个结果是否能回溯到基础能力和真实数据；
- 异常、缺失和部分可用状态是否有承接位置；
- 是否仍然遵守社交网络分析与流行度预测的数据边界。

复盘只针对业务模块设计，不涉及代码、数据库或页面实现。

## 2. 业务链路复盘结论

### 2.1 内置数据主链路

```text
B01 数据集入口与能力说明
    ↓
B02 网络总览
    ↓
┌──────────────┬──────────────┬──────────────┐
↓              ↓              ↓
B03 关系网络  B04 重要节点  B06 推文互动
↓              ↓              ↓
└──────→ B05 用户详情 ←──────┘
                ↓
        B07 主题与网络联动
                ↓
        S04 导出当前结果
```

### 2.2 用户探索链路

```text
进入工作台
→ 查看数据集说明和能力矩阵
→ 查看网络总览
→ 搜索或选择用户
→ 查看局部关注网络
→ 查看重要性指标
→ 查看用户详情
→ 查看用户推文和互动
→ 查看主题相关结果
→ 导出当前筛选结果
```

### 2.3 主题探索链路

```text
输入主题
→ 匹配相关推文
→ 汇总已关联作者
→ 查看主题互动表现
→ 提取主题相关用户
→ 查看这些用户之间的真实关注关系
→ 进入用户详情或推文详情
```

主题链路中的关系图只表示真实关注边，不表示关键词共现、传播路径或因果关系。

## 3. 模块职责总表

| 模块 | 核心问题 | 主要输入 | 主要输出 | 明确不负责 |
| --- | --- | --- | --- | --- |
| B01 | 当前使用什么数据，能做什么 | 数据集、质量报告、能力矩阵 | 数据集摘要、能力入口 | 具体分析结果 |
| B02 | 网络整体规模和质量如何 | 网络统计、互动摘要 | 规模、密度、质量摘要 | 全量关系图、节点排行 |
| B03 | 某用户关注了谁，谁关注他 | 用户、关系、局部筛选 | 有向局部网络 | 重要性排行 |
| B04 | 哪些节点在某项指标上突出 | 网络指标、账户字段、互动汇总 | 分指标排行、重要原因 | 综合影响力、用户完整详情 |
| B05 | 这个用户是谁，为什么出现在排行 | 用户 ID、网络指标、推文、主题摘要 | 用户详情和跨模块联动 | 粉丝增长、立场和传播因果 |
| B06 | 哪些推文和用户互动较高 | 推文互动统计、筛选条件 | 推文排行、用户排行、时间分布 | 综合互动分、主题语义 |
| B07 | 某主题关联哪些推文和用户 | 主题查询、文本结果、关注关系、互动结果 | 主题推文、用户、互动和关系子图 | 传播路径、主题影响力 |

## 4. 边界校验结果

### 4.1 B01 与 B02

**边界结论：清晰。**

- B01 只负责数据集身份、来源、质量摘要和能力入口；
- B02 负责加载后的总体统计；
- B01 不提前展示网络指标明细；
- B02 不重新解释数据集来源。

### 4.2 B02 与 B03

**边界结论：清晰。**

- B02 展示网络规模和结构摘要；
- B03 展示用户可探索的局部关系图；
- B02 不嵌入完整关系图；
- B03 不承担全局网络总览。

### 4.3 B03 与 B04

**边界结论：清晰。**

- B03 负责“关系如何连接”；
- B04 负责“哪些节点在某项指标上突出”；
- B03 可以显示节点指标作为筛选辅助；
- B03 不生成排行结论；
- B04 不负责绘制完整关系图。

### 4.4 B04 与 B05

**边界结论：清晰。**

- B04 负责多指标排行和简要重要原因；
- B05 负责单个用户的完整解释；
- B04 点击节点进入 B05；
- B05 不重新定义排行指标。

### 4.5 B05 与 B06

**边界结论：清晰。**

- B05 展示单个用户的互动摘要和代表性推文；
- B06 展示全局或筛选范围内的推文与用户互动排行；
- B05 可以跳转 B06；
- B06 不重复承载完整账户资料。

### 4.6 B06 与 B07

**边界结论：清晰。**

- B06 负责互动指标的统计和展示；
- B07 负责确定主题相关推文集合，再调用 B06 统计互动；
- B07 不自行定义互动公式；
- B06 不判断主题归属。

### 4.7 B05 与 B07

**边界结论：清晰，但需保留口径提示。**

- B05 可以展示用户主要关键词和主题摘要；
- B07 负责完整主题查询与主题用户网络；
- 用户关键词不能被解释为用户立场或主题归属；
- 主题相关用户不能自动称为主题核心节点。

## 5. 数据流和调用规则校验

### 5.1 统一数据来源

所有 B01-B07 必须使用：

```text
F03 规范化用户、关系和推文结果
```

禁止业务模块直接读取：

```text
原始 CSV
原始 JSONL
following_list 原始字符串
```

### 5.2 统一指标来源

```text
F04 → 网络结构指标
F05 → 推文互动指标
F06 → 文本和主题指标
S03 → 指标名称、公式和解释
```

业务模块不得自行重新计算或改写口径。

### 5.3 统一筛选来源

筛选条件由 S05 统一维护，包括：

- 用户；
- 时间；
- 指标；
- Top-K；
- 邻居层级；
- 语言；
- 主题；
- 互动阈值。

S04 导出必须复用当前筛选范围，不能生成与页面不同的结果。

### 5.4 统一状态来源

所有业务模块使用 S06 的状态定义，并参考 S02 的能力状态：

```text
可用
部分可用
空结果
不可用
加载中
失败
```

一个指标失败时，优先采用指标级降级，不关闭整个业务模块。

## 6. 关键数据边界复核

### 6.1 关系边界

- 节点：用户和必要的外部节点；
- 边：真实用户关注关系；
- 方向：关注者 → 被关注者；
- 外部节点保留但标记资料缺失；
- 不添加装饰性关系；
- 不把关系图解释为传播路径。

### 6.2 推文边界

- 分析层按 `tweet_id` 去重；
- 原始层保留重复记录并标记；
- 推文数量使用“当前采集样本”表述；
- 用户排行只使用作者成功关联的推文；
- 未归属推文可以进入全局推文统计；
- 未归属推文不进入默认用户排行和主题用户网络。

### 6.3 互动边界

- 点赞、评论、转发分别统计；
- 书签字段当前暂无有效数据；
- 首版不定义综合互动分；
- 不根据互动值推导社会影响力；
- 不根据静态粉丝数推导增长。

### 6.4 文本边界

- 首版采用文本清洗、关键词和 TF-IDF；
- 支持中文、英文及混合文本；
- 主题相关用户来自匹配推文的已关联作者；
- 关键词共现不等于传播关系；
- 主题结果不代表立场、因果或全网趋势。

### 6.5 用户上传边界

- 支持 users、relationships、tweets 三类文件；
- 允许部分文件；
- 根据 S02 自动降级能力；
- 首版仅当前分析会话使用；
- 不永久保存上传数据集；
- 上传失败不影响内置数据；
- 支持导出当前分析结果。

## 7. 首版业务闭环复核

首版最小闭环已形成：

```text
真实数据加载
→ 数据集说明和质量提示
→ 网络总览
→ 局部关注网络
→ 多指标重要节点
→ 用户详情
→ 推文互动
→ 主题检索和关系联动
→ 当前结果导出
```

### 首版已明确包含

- 内置“智库社交网络数据”；
- 数据质量与能力说明；
- 网络总览；
- 有向局部关系网络；
- 入度、出度、PageRank；
- 原始账户字段对照；
- 用户详情；
- 点赞、评论、转发独立统计；
- 关键词和 TF-IDF；
- 主题相关推文、用户和关注子图；
- CSV、JSON 和可打印摘要导出。

### 首版明确不包含

- 中介中心性；
- 社区发现；
- 综合互动分；
- 综合网络影响力分；
- 粉丝增长；
- 传播路径推断；
- 复杂语义模型；
- 永久保存用户上传数据集；
- 自动生成无证据研究报告。

## 8. 复盘发现的待注意事项

本次未发现必须拆分或合并的业务模块。F07 和 F08 已完成独立规划，实施前仍需要锁定以下工程化口径：

1. 用户上传数据的三文件字段映射需要在 F02/F03 阶段冻结；
2. PageRank 的具体参数需要在指标口径阶段固定并版本化；
3. 多语言停用词和分词规则需要在 F06 阶段记录版本；
4. 主题样本状态的实际阈值需要用真实数据验证；
5. 网络总览的外部节点统计口径需要在 F04 阶段固定；
6. 导出推文原文时需要再次核对最终数据说明和授权范围；
7. F07 的缓存生命周期和 F08 的接口响应结构需要在技术设计阶段转化为可验收契约。

这些事项不会改变 B01-B07 的总体边界，但会影响后续验收口径。

## 9. 复盘后的推荐交付顺序

```text
B01 数据集入口与能力说明
→ B02 网络总览
→ B03 用户关注网络
→ B04 重要节点分析
→ B05 用户详情
→ B06 推文与互动分析
→ B07 主题与网络联动
→ S04 统一导出验收
```

其中 B01-B03 可以形成网络基础演示，B04-B06 形成节点和互动分析闭环，B07 作为主题研究扩展接入。

## 10. 最终复盘结论

本次边界校验结论为：

```text
B01-B07 业务链路闭合
模块职责无严重重叠
基础能力、支撑模块和业务模块分层明确
所有业务结果均有对应数据或算法来源
局部视图与全局总览边界清晰
网络指标、账户字段、互动指标和主题指标已分开
异常、空数据和部分可用状态有统一承接
用户上传数据与内置数据保持会话隔离
社交网络分析与流行度预测保持独立
```

因此，B01-B07 可以作为后续技术设计和阶段实施的稳定业务基线。
