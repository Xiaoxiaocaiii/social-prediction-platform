# 负责人反馈与后续改进方向

## 1. 文档目的

本文档汇总当前负责人提出的页面、功能和产品定位问题，作为后续改进社交网络分析模块及首页信息架构的依据。

本阶段的核心目标是：

> 让用户先看懂数据、分析步骤和结果边界，再进行具体操作。

重点不是简单增加指标数量，而是让平台真正体现“基于关系结构的社交网络分析”，同时明确流行度推演和社交网络分析是两条不同的分析流程。

## 2. 当前主要问题

### 2.1 社交网络分析偏向表格统计

当前页面主要展示：

- 用户数量；
- 关注关系数量；
- 入度和出度排行；
- PageRank 排行；
- 粉丝数、关注数；
- 推文点赞、评论和转发统计。

这些内容有一部分可以通过 Excel 排序完成，尚未充分体现社交网络分析的核心价值：

- 用户之间如何连接；
- 用户是否形成社群；
- 哪些用户处于社群核心；
- 哪些用户连接了不同社群；
- 网络整体是集中、分散还是分群。

### 2.2 数据集名称和来源不明确

当前页面使用“当前数据集”等模糊表述，用户无法立即知道这是哪个数据集。

内置数据集应明确命名为：

```text
智库社交网络数据集
```

同时说明数据内容包括：

- 用户信息；
- 用户之间的关注关系；
- 推文和互动样本。

### 2.3 “部分可用”解释不够清楚

页面只显示“部分可用”，但没有明确告诉用户：

- 哪些数据可以使用；
- 哪些数据没有纳入分析；
- 为什么不能使用；
- 当前结果基于哪些数据生成。

“部分可用”不应被理解为系统故障，而应解释为数据存在缺失、重复、冲突或无法关联，但主体数据仍可参与分析。

### 2.4 指标名称和专业术语不够直观

目前的“用户记录”“关系候选”“推文样本”“入度”“出度”等术语，对普通用户不够友好。

例如，用户需要理解：

- 入度是当前数据中有多少条关系指向某个用户；
- 出度是当前数据中某个用户指向了多少其他用户；
- 入度和出度来自当前关系表；
- 粉丝数和关注数来自原始账号资料；
- 两组指标的统计范围可能不同。

### 2.5 PageRank 状态缺少说明

“已收敛 · 27 次”容易让用户误解为 27 次操作或 27 分。

需要说明：

- PageRank 通过多轮迭代计算节点在网络中的结构位置；
- 每轮会根据其他节点的重要程度更新当前节点分数；
- 结果变化足够小后，算法认为结果稳定；
- 27 次是本次网络达到稳定所需的迭代轮数；
- 迭代次数越多不代表节点越重要。

### 2.6 导出工具位置不合理

当前把导出功能集中放在数据集入口页，用户还需要额外选择结果范围。

负责人建议将导出按钮放到各个分析模块右上角，让用户直接导出当前模块的结果。

### 2.7 能力矩阵页面价值不高

“分析能力状态 / Capability Matrix”更像内部系统状态，不像用户真正需要阅读的分析内容。

负责人倾向于删除整块能力矩阵，并将其中有价值的解释分配到原本对应的页面：

- 数据可用范围放到数据质量部分；
- 网络限制放到网络总览；
- 入度、出度和排序依据放到重要节点分析；
- 推文作者关联问题放到互动分析；
- TF-IDF 和主题关系边界放到主题分析。

### 2.8 用户数量应以 626 为准

此前爬虫人员反馈的 616 个用户是记忆偏差，经过核对后确认当前合并数据集实际包含 **626 个用户**。

因此：

- 页面显示的用户数 `626` 是正确的；
- 不需要将用户数修改为 `616`；
- 页面仍应说明“626”指当前合并数据集中实际识别并规范化后的用户数；
- 后续如更换数据版本，应重新核对用户 ID 数量和统计口径。

### 2.9 首页把两个方向写成同一套流程

当前首页使用：

```text
选择研究方向 → 输入研究对象 → 查看分析结果
```

这会让用户误以为流行度推演和社交网络分析需要相同的输入和步骤。

实际上：

- 流行度推演输入的是研究主题；
- 社交网络分析输入的是内置数据集或用户自定义数据集；
- 流行度推演输出的是历史案例和热度参考趋势；
- 社交网络分析输出的是关系网络、社群和节点角色。

两条流程必须在首页拆开说明。

## 3. 社交网络分析的产品定位调整

后续不应只把社交网络分析定位成“查看粉丝数和点赞量”，而应定位为：

> 基于真实用户关系数据的网络结构、社群划分和节点角色分析工具。

它需要回答的问题包括：

- 谁处于网络中心；
- 谁连接了不同群体；
- 用户之间形成了哪些社群；
- 社群之间是否存在连接；
- 网络整体是集中还是分散；
- 关系结构和账号资料指标是否一致。

## 4. 社交网络分析需要新增的核心能力

### 4.1 独立的大型关系网络图

应新增一个单独的“关系网络图”页面或独立分析区域，避免和基础统计、排行榜挤在一起。

图中应包含：

- 用户作为节点；
- 关注关系作为有向边；
- 全部节点；
- 社群淡色背景圈；
- 节点和社群的图例；
- 节点搜索；
- 点击节点查看详情。

建议支持：

- 鼠标滚轮缩放；
- 拖拽平移；
- 节点拖动；
- 搜索后定位节点；
- 点击节点展开局部关系；
- 隐藏或显示关系边；
- 查看全局网络和局部网络两种模式。

当前数据规模约为 626 个节点和 12,963 条关系，全量展示可能较密集，因此需要：

- 使用大尺寸画布；
- 使用 Canvas 或 WebGL 等适合大量元素的渲染方式；
- 降低边的透明度；
- 根据缩放级别控制边和标签显示；
- 默认显示全局结构，点击后查看局部关系。

### 4.2 社群发现和可视化

应根据关注关系自动识别相对紧密的群体，并展示：

- 社群数量；
- 每个社群的节点数；
- 社群核心用户；
- 社群内部关系数；
- 社群之间的关系数；
- 社群划分质量指标，如模块度。

可视化建议：

- 不同社群使用不同但低饱和度的颜色；
- 使用淡色背景圈标识社群范围；
- 节点颜色与社群图例对应；
- 允许选择单个社群进行聚焦。

必须在页面说明：

> 社群表示当前关系结构中相对紧密的节点集合，不直接等同于真实组织、政治阵营、兴趣群体或利益集团。

### 4.3 核心节点和桥接节点

除了粉丝数和入度排行，还应识别：

- 社群内部连接较多的核心节点；
- 连接不同社群的桥接节点；
- 网络边缘节点；
- PageRank 高但粉丝数不一定高的结构性节点。

可使用：

- 度中心性；
- PageRank；
- 介数中心性；
- 跨社群连接数；
- 社群内部连接比例。

页面应将这些指标解释为网络角色，而不是直接称为“真实影响力”。

### 4.4 网络结构指标

基于现有用户和关系数据，可以继续增加：

- 连通分量；
- 最大连通子图；
- 平均路径长度；
- 平均度；
- 聚类系数；
- 关系互惠性；
- 核心—边缘结构；
- 社群模块度。

这些指标用于描述网络结构，不代表关系亲密程度、社会影响力或因果关系。

## 5. 两类数据入口必须分开

社交网络分析应明确提供两个入口：

### 5.1 使用内置数据集

入口名称建议为：

```text
使用智库社交网络数据
```

用户点击后直接进入内置数据的分析流程。

需要展示：

- 数据集名称；
- 数据来源或整理说明；
- 数据版本；
- 用户数；
- 关注关系数；
- 推文数；
- 数据质量；
- 可用分析范围。

### 5.2 上传自定义数据集

入口名称建议为：

```text
上传我的数据集
```

用户上传后，系统应：

1. 检查文件格式；
2. 识别字段；
3. 规范化用户和关系；
4. 生成数据质量报告；
5. 说明哪些字段可用；
6. 根据字段完整性开放对应分析；
7. 进入统一的网络分析页面。

内置数据和自定义数据应使用同一套分析说明和数据质量口径。

## 6. 数据质量说明的调整方案

### 6.1 位置调整

数据质量说明应放在第一部分之前，作为进入分析前的使用说明。

建议页面顺序：

```text
00 / 数据质量与使用说明
01 / 数据集入口
02 / 网络总览
03 / 关系网络图
04 / 用户关注网络
05 / 重要节点分析
06 / 用户详情
07 / 推文互动分析
08 / 主题分析
```

### 6.2 展示内容

不要只显示“部分可用”，应至少说明：

- 原始记录数；
- 有效记录数；
- 重复记录数；
- 冲突记录数；
- 缺失字段数；
- 成功关联数；
- 未关联数；
- 纳入分析的记录数；
- 未纳入分析的记录数；
- 未纳入原因。

### 6.3 用户易懂的文案

例如：

```text
推文记录冲突：72 条
相同推文 ID 对应的内容字段不一致，这些记录不会作为可靠样本参与相关分析。
```

对于整体状态：

```text
主体数据可用于分析，部分关系、用户或推文记录存在缺失、重复、冲突或未关联情况。
```

## 7. 页面文字和指标名称调整

建议统一使用以下名称：

| 当前名称 | 建议名称 |
|---|---|
| 当前数据集 | 智库社交网络数据集 |
| 数据集状态 | 数据状态 |
| 用户记录 | 用户数 |
| 规范化用户样本 | 已识别用户 |
| 关系候选 | 关注关系数 |
| 关注关系候选数 | 已记录关注关系 |
| 推文样本 | 推文数 |
| 当前采集样本 | 已采集推文 |
| 入度 | 数据内被关注数（入度） |
| 出度 | 数据内关注数（出度） |
| PageRank | 网络结构重要度 |
| PageRank 状态 | PageRank 计算状态 |
| 分析能力状态 | 当前数据支持的分析功能 |

### 7.1 网络密度说明

页面需要说明网络密度取值范围为 `0～1`：

- `0`：没有有效关系；
- 越接近 `1`：用户之间的关系越密集；
- `1`：理论上所有可能的关系都存在；
- 当前 `0.0331`：实际有效关系约占理论可能关系的 `3.31%`，说明当前网络整体较稀疏。

### 7.2 孤立节点说明

```text
孤立节点：当前数据中没有记录到任何关注关系的用户数量。
```

这是数量指标，不是 `0～1` 的比例。

### 7.3 外部节点说明

```text
外部节点：关系数据中出现，但无法在用户资料表中找到对应资料的节点数量。
```

当前为 `0` 时，说明已记录的关系节点都能找到用户资料。

### 7.4 入度和出度说明

```text
入度 = 当前数据中记录的指向该用户的关注关系数。
出度 = 当前数据中记录的该用户指向其他用户的关注关系数。
```

必须同时说明：

```text
入度和出度来自当前关系数据；粉丝数和关注数来自用户原始资料，两者统计范围可能不同。
```

### 7.5 PageRank 说明

建议显示：

```text
PageRank 计算状态：已完成
27 轮迭代后结果稳定
```

说明文字：

> PageRank 通过多轮迭代计算节点在网络中的结构位置，直到结果基本稳定。迭代次数受网络规模和关系结构影响，次数多不代表节点更重要。

## 8. 导出功能调整方案

删除或弱化数据集入口页中的统一导出区域，改为各分析模块独立导出。

建议：

- 网络总览右上角：导出网络指标、节点和边；
- 关系网络图右上角：导出当前网络节点、关系和社群信息；
- 用户关注网络右上角：导出当前用户及其关系；
- 重要节点分析右上角：导出当前排序结果；
- 推文互动分析右上角：导出互动统计和排行；
- 主题分析右上角：导出关键词、匹配推文和相关关系；
- 数据质量部分右上角：导出质量报告。

用户点击哪个模块的导出按钮，就导出该模块的结果，不再额外选择“结果范围”。

格式可以保留：

- CSV；
- JSON；
- 可打印摘要。

## 9. 能实现与不能实现的边界

### 9.1 当前可以实现

- 用户、关系和推文统计；
- 网络密度、孤立节点和连通结构；
- 入度、出度和 PageRank；
- 用户关系查询；
- 互动数量统计；
- 关键词和 TF-IDF；
- 关系网络图；
- 社群发现；
- 社群核心节点；
- 桥接节点识别；
- 网络结构指标。

### 9.2 需要补充数据后实现

以下功能需要互动对象、传播链路或时间序列：

- 谁点赞了谁；
- 谁评论了谁；
- 谁转发了谁；
- 真实传播路径；
- 网络动态演化；
- 未来关系预测；
- 传播效果预测；
- 同伴效应和影响因果。

### 9.3 当前不能可靠声称

当前不能仅凭静态关系和聚合互动数据得出：

- 谁是真实社会影响力最大的人；
- 某个社群对应真实组织或阵营；
- 某个用户导致了某条内容传播；
- 某条内容一定会爆；
- 某个用户未来一定会成为核心；
- 某个用户一定会与另一个用户建立关系。

页面应明确使用：

```text
当前数据中
历史样本显示
在本数据集范围内
网络结构上
```

避免使用未经验证的确定性表述。

## 10. 首页改进方案

首页必须将流行度推演和社交网络分析拆成两个独立方向。

### 10.1 流行度推演流程

建议首页显示：

```text
流行度推演
输入研究主题 → 匹配历史案例 → 查看热度趋势
```

具体说明：

1. 输入研究主题；
2. 从历史视频数据中检索相似内容；
3. 读取相关历史案例的真实热度序列；
4. 生成 30 天热度参考趋势；
5. 查看峰值日期、趋势变化和参考案例。

### 10.2 社交网络分析流程

建议首页显示：

```text
社交网络分析
选择数据集 → 检查数据质量 → 查看网络与社群
```

具体说明：

1. 使用智库社交网络数据，或上传自己的数据集；
2. 查看数据质量和可用范围；
3. 查看用户节点、关注关系和网络结构；
4. 发现社群、核心节点和桥接节点；
5. 查看推文互动与主题分析。

首页不再使用统一的：

```text
选择研究方向 → 输入研究对象 → 查看分析结果
```

因为这套描述无法准确覆盖两个模块的不同输入、分析过程和结果类型。

## 11. 后续改进优先级

### P0：先统一概念和数据口径

- 固化当前数据集用户数为 626，并在页面说明统计口径；
- 确认智库数据集名称和来源说明；
- 明确用户数、关系数和推文数的统计口径；
- 调整数据质量说明；
- 修改专业术语和页面文案。

### P1：调整页面结构和入口

- 删除能力矩阵页面；
- 将数据质量移到第一部分之前；
- 将内置数据和自定义数据拆成两个入口；
- 将首页两个分析方向拆成两条流程。

### P2：补充真正的网络分析

- 增加全量关系网络图；
- 增加缩放、平移、搜索和节点详情；
- 增加社群发现和淡色社群圈；
- 增加核心节点和桥接节点；
- 增加网络结构指标。

### P3：调整导出和交互

- 将导出按钮放到各模块右上角；
- 导出当前模块结果；
- 删除统一结果范围选择；
- 增加导出内容说明。

### P4：补充数据后再考虑高级能力

- 互动双方网络；
- 传播路径；
- 动态网络；
- 链路预测；
- 影响和因果分析。

## 12. 验收标准

后续改进完成后，应满足：

1. 用户进入首页就能区分流行度推演和社交网络分析；
2. 用户能明确知道内置数据集名称是“智库社交网络数据集”；
3. 用户能在分析前看到数据质量和可用范围；
4. 页面不再只展示“部分可用”而没有原因；
5. 用户能理解用户数、关注关系数和推文数；
6. 用户能理解网络密度、孤立节点、外部节点和 PageRank；
7. 入度、出度与粉丝数、关注数的统计范围有明确区分；
8. 社交网络分析有独立的大型关系网络图；
9. 网络图能够展示节点、关系和社群圈；
10. 用户能够通过缩放、平移、搜索和点击查看网络；
11. 结果导出按钮位于对应分析模块；
12. 页面明确说明哪些结论当前不能可靠得出；
13. 页面用户数显示为 626，并明确其对应当前合并数据集的统计口径；
14. 现有内置数据和用户自定义数据使用一致的质量说明和分析边界。

## 13. 总结

后续改进的核心方向不是继续增加排行榜，而是完成以下转变：

```text
从“指标和排行展示”
转向“数据质量说明 + 关系网络图 + 社群结构 + 节点角色分析”
```

同时，首页需要把两个产品方向讲清楚：

```text
流行度推演：主题 → 历史案例 → 热度参考趋势
社交网络分析：数据集 → 数据质量 → 网络与社群结构
```

这样用户才能在操作前理解平台使用什么数据、如何分析、能得到什么结果，以及哪些结论不能从当前数据中直接推导。
