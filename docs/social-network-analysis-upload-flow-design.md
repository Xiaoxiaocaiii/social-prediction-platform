## 1. 产品边界

- 首版开放用户上传，定位为使用当前分析会话进行即时分析的真实产品能力。
- 上传数据仅用于当前分析会话，不永久保存；不提供历史版本、跨会话加载或多用户共享。
- 内置“智库社交网络数据”保持默认数据集。上传、解析、质量检查或会话切换失败均不得修改内置数据。
- 上传数据不得写入 `all_csv/`、`csv/`、预测模块数据库、Repository、缓存或 `/api/predict` 链路。
- 用户负责说明数据来源及其使用边界。平台不得根据文件名、目录、字段或内容推断来源、授权主体或真实时间范围。
- 本设计不改变既有字段 schema、指标定义、规范化规则或永久存储边界。后续实现已将上传会话接入全局关系图与 Louvain/Clique 工作流，当前会话数据仍不作为永久数据集保存。

## 2. 用户流程

1. 用户进入 B01 数据集入口。内置数据仍处于当前选中状态；上传入口是次级操作。
2. 用户选择一个或多个文件，为每个文件明确选择 `users`、`relationships` 或 `tweets` 角色。角色不从文件名推断。
3. 页面显示格式、文件数、大小、来源说明和当前会话使用提示；来源与责任提示展示即可继续，不要求强制勾选。用户可直接提交或取消。
4. 服务端在独立临时暂存区验证并读取文件，检查标准字段，运行规范化和质量报告。此阶段不切换当前数据集。
5. 验证通过后建立短期上传会话，展示质量预览和能力状态。用户可以返回修改文件，或明确选择“使用此数据集分析”。
6. 用户确认后，工作台将当前数据集切换到该上传会话；B01-B07 后续请求使用同一 `datasetId`、`datasetVersion` 和 `sessionId`。
7. 用户可切回内置数据集并结束上传会话。取消、上传失败或会话过期时，工作台保持或恢复内置数据集，并明确提示原因。

页面状态至少包括：`idle`、`validating`、`uploading`、`preview`、`active-upload`、`failed`、`expired`。加载、校验和预览期间保留当前已选数据集，不以未完成上传替换分析上下文。

## 3. 文件选择与校验

### 3.1 文件数量和角色

- 负责人已确认同一逻辑角色允许选择多个文件。
- `users`、`relationships`、`tweets` 三类角色均可省略，允许部分文件组合；最终模块能力由既有能力矩阵根据有效数据判定，不因文件“存在”就宣称该能力可用。
- 单次上传最多 10 个文件；这 10 个文件可分配到一个或多个角色。
- 文件角色由用户显式选择；名称只作为原始文件追溯信息。
- 负责人已确认同一角色的多个文件逐文件校验后合并为一个逻辑数据集；每个文件保留自己的来源文件名和行号。

### 3.2 格式与内容

- 仅支持 `.csv`、`.jsonl`，大小写扩展名可兼容；编码仅 UTF-8 或 UTF-8 BOM。
- CSV 必须有表头；JSONL 每行必须是一个对象；不支持整文件 JSON 数组。
- 不支持 Excel、压缩包、XML、GBK/GB18030、UTF-16、无表头 CSV、自动分隔符猜测或自由格式转换。
- 扩展名和浏览器 MIME 仅用于前置提示，服务端必须读取并验证真实内容和编码。
- 同角色文件逐个校验该角色的必需标准字段；可选字段可以因文件而异，缺少字段按既有缺失规则记录质量状态，不以空字符串或 0 虚构补齐。全部通过文件级校验后再合并规范化，去重规则应用于合并后的逻辑数据集。
- 空文件、格式与内容不符、必需表头缺失或无法解析作为文件级阻断错误；任一文件触发该错误时整批拒绝，不创建可激活数据集并清理本次暂存。
- 行级非法记录保留在质量报告中；符合规范的记录可以继续进入预览，异常记录不得静默修复或参与不适用的分析。

### 3.3 大小限制

负责人已选择单文件 `128MiB`、单次请求 `160MiB` 作为社交网络上传设计上限，支持接近当前内置数据的规模。E3 已在项目本机运行模式下完成单并发容量验证；Spring MVC 全局 `10MB`/`12MB` 配置保持不变。该结果不代表并发容量或峰值内存验收，相关风险属于 E5。

只读检查发现内置合并样例中的 `all_tweets_raw.jsonl` 约 `111.72MiB`，还未计入用户与关系文件；现有 `12MB` 请求上限不能承载同等规模的单次上传。该样例仅作为容量讨论依据。

容量设计至少应容纳当前样例规模：最大单文件约 `111.72MiB`，全部三类 JSONL 文件合计约 `112.11MiB`。本机测试已验证一个 `128MiB` 文件加一个 `31MiB` 文件的请求可处理至 `ready`，并验证 `108.14MiB`、237,840 条推文的上传与质量预览；结果适用于当前本机单并发配置。不得只放宽浏览器限制或静默修改全局 multipart 配置。浏览器预检只能提前提示，服务端限制才是最终判定。

## 4. 字段映射与来源确认

- 字段映射步骤负责把文件指定为逻辑角色，并展示解析出的标准字段；不得按文件名、字段含义或列位置猜测角色和别名。
- `users`、`relationships`、`tweets` 的字段名按既有契约精确匹配大小写。必需字段缺失为阻断错误；可选字段缺失显示为信息或能力限制。
- `relationships` 使用 `source_user_id`、`target_user_id` 标准边表；`source_user_id → target_user_id` 表示 source 关注 target。
- `tweets.user_id` 是标准作者字段；不得将内置数据的 `source_folder` 适配规则推广到用户上传文件。
- 显示必需字段识别结果、可选字段、未识别列和字段错误。未知列不自动映射；是否保留在原始临时记录中遵循既有追溯契约，不进入业务分析字段。
- 上传前展示来源说明输入项，可留空；留空后报告为“用户未提供”。展示来源与责任提示即可继续，不要求强制勾选。平台不核验来源或授权；不得根据文件名、目录、字段或内容推断来源。
- 上传及预览提示使用既有边界文案：“用户上传数据仅用于当前分析会话，首版不会永久保存上传文件。”

## 5. 上传会话与失败隔离

- 上传文件先写入会话级唯一临时暂存区；禁止使用用户提供的路径作为服务端目标路径，也不向前端返回服务器临时绝对路径。
- 任一文件发生文件级阻断错误时整批拒绝，清理本次暂存，不修改内置数据，不改变当前数据集选择，不写入永久数据库或预测模块；行级问题继续由质量报告标注。
- 成功生成预览后才注册 `datasetType=upload_session` 的短期会话，响应携带 `sessionId`、`datasetId`、`datasetVersion`、质量摘要和 `expiresAt`。
- 上传会话沿用现有生命周期契约：idle TTL 2 小时、hard TTL 24 小时；会话结束或过期后，文件、规范化临时数据、质量报告和会话缓存均应清理。
- 创建会话与激活数据集是两个独立动作。创建或预览不得自动切换全局当前数据集；仅用户确认后才能激活。
- 当前注册表的 `createUploadSession` 会立即修改当前数据集指针，而工作区服务尚拒绝上传会话。E3 接入前必须将“创建会话”和“选择当前数据集”拆开，并保证预览、失败和取消不会令工作区指向不可分析会话。

## 6. 质量预览

预览必须来自服务端读取、规范化和质量报告，不由前端根据文件名或表头自行判定能力。至少显示：

- 数据集临时名称、会话状态、来源说明状态和过期时间；
- 每个角色的文件名、格式/编码、表头状态、原始行数、读取成功数、跳过数和错误数；
- 用户、关系、推文的原始记录数、有效记录数、去重/冲突/外部/未关联统计，以及可定位的逻辑文件名和行号；
- 文件组合下 B01-B07 的能力状态、受限或不可用原因；
- 全部警告、阻断错误和明确的空值/零值状态。

质量预览默认不回显整行原始内容或完整推文文本。详情使用逻辑文件名、行号、错误码和经脱敏的原因；不得返回服务器路径、堆栈或临时目录。

存在行级错误但仍有有效数据时，可以进入 `available_with_warnings` 或 `partial` 预览，由质量报告和能力矩阵说明影响；所有选中文件均无可用记录时标记为 `unavailable`，允许查看原因，但禁止激活分析。

## 7. 当前数据集切换

- 工作台当前上下文是单一数据集；模块请求统一携带该数据集的 ID、版本，上传会话请求另绑定 `sessionId`。
- 内置数据集始终可选。预览中的上传数据不是当前数据集，直到用户显式确认。
- 激活上传数据成功后，B01-B07 使用同一数据集上下文；不能出现网络模块读上传数据、互动或主题模块仍读内置数据的混合状态。
- 切回内置数据集时先更新工作台上下文，再按用户选择结束上传会话；结束会话不删除内置文件或内置缓存。
- 上传会话过期、被关闭或读取失败时，清除失效上下文并回退内置数据集，提示用户该上传会话已失效；不得把内置数据标记为上传失败。
- 当前设计不承诺刷新浏览器或关闭浏览器后恢复上传会话；会话仍按服务端 TTL 清理。

## 8. API 与实现交接

- 上传入口沿用现有契约草案 `POST /api/social-network/datasets/upload`，采用 multipart/form-data；响应至少包含会话、数据集版本和过期信息。
- 上传请求必须显式传递每个文件的逻辑角色；来源说明可选。来源与责任提示展示即可继续，不传递或强制要求额外的用户确认状态。文件角色的 multipart 编码方式、预览响应字段及数据集激活/切回接口由 E3 同步更新正式 API 契约；不得仅以 `files[]` 顺序或文件名推断角色。
- 质量摘要和详情复用既有 `/datasets/{datasetId}/quality/...` 资源设计；上传预览不得绕过质量报告或能力矩阵。
- 所有错误响应沿用社交网络 API 统一包络和错误脱敏边界。大小超限返回 HTTP 413；不支持格式使用既有 `SN_UNSUPPORTED_FORMAT`；会话失效使用既有 `SN_DATASET_SESSION_EXPIRED`。
- E2 不实现端点、临时文件清理、扫描器、前端页面、数据库或缓存；实际安全处理与清理由 E5 落实。

## 9. 后续验收边界

1. E3 已冻结文件角色、预览结果、显式激活/切回数据集契约，并完成网络、互动、主题模块一致性及本机容量验收。
2. E5 已完成当前会话上传的异常文件处理、全量临时文件清理、过期任务清理、来源责任提示核验及本机单 worker 背压/资源验收；两份真实大文件同时提交时解析按队列串行完成，不表示支持多 worker 并行解析。不得意外改变预测模块上传边界。

以上是当前阶段边界说明，不改变已完成的 E3 验收状态。

## 10. 负责人讨论记录

**本轮已确认的方向**：

- 同一逻辑角色允许选择多个文件。
- 首版容量目标应支持接近当前内置数据规模；采用社交网络专属上限，选择单文件 `128MiB`、单次请求 `160MiB`，须经资源测试后才能开放。
- 单次上传最多 10 个文件。
- 上传后先展示质量预览，由用户明确确认是否激活该数据集。
- 任一文件出现文件级阻断错误时整批拒绝。
- 同角色文件逐文件校验后合并为一个逻辑数据集，保留每个文件的来源文件名和行号；可选字段缺失按既有规则报告。
- 来源与责任提示展示即可继续；来源说明可留空，不要求强制勾选，空值标记为“用户未提供”。

以上方向性选择已由负责人确认，E2 设计完成。随后 E3 已实现并在本机单并发模式完成 128MiB 单文件、160MiB 请求上限边界及代表性数据验证；更高并发与峰值资源能力仍须在 E5 单独验收。
