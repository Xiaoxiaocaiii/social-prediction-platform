# 社交网络分析功能边界说明

## 1. 文档目的

本文档用于说明当前社交网络分析模块能够实现的功能、可以继续扩展的功能，以及由于数据条件不足而不能可靠实现的功能。

文档重点回答三个问题：

1. 当前系统已经完成了什么；
2. 基于现有数据还能实现什么；
3. 哪些功能需要补充数据，哪些结论当前不能直接得出。

## 2. 当前数据基础

当前内置数据集包含三类核心数据：

| 数据类型 | 主要内容 | 当前用途 |
|---|---|---|
| 用户数据 | 用户 ID、用户名、显示名称、粉丝数、关注数、推文总数等 | 用户资料和账号属性分析 |
| 关系数据 | 用户之间的关注关系 | 有向网络、入度、出度、PageRank 和社群分析 |
| 推文数据 | 推文内容、发布时间、点赞数、评论数、转发数等 | 文本主题和互动统计 |

当前数据集的基础规模以实际加载结果为准，页面目前显示：

- 用户：626；
- 关注关系候选：12,963；
- 推文样本：237,840。

这里的“用户数”来自合并后的用户信息表，不等同于爬虫阶段的种子账号数或成功采集账号数。若不同来源出现数量差异，应先对账号 ID 和数据版本进行核对。

## 3. 当前已经实现的功能

### 3.1 数据集入口和质量检查

当前系统可以：

- 读取内置用户、关系和推文数据；
- 统计用户、关系和推文数量；
- 识别重复用户 ID；
- 识别重复关系和自环关系；
- 识别重复但字段冲突的推文；
- 检查用户、关系和推文之间的关联情况；
- 对数据集标记为“可用”“部分可用”或“不可用”；
- 展示缺失、冲突、重复和未关联等质量问题。

“部分可用”表示主体数据可以用于分析，但部分记录存在缺失、冲突或无法关联的情况，并不表示整个数据集不可用。

### 3.2 网络整体统计

当前系统可以计算：

- 用户节点数；
- 有效关系数；
- 网络密度；
- 孤立节点数；
- 外部节点数；
- PageRank 计算状态。

这些指标用于描述网络整体结构，不用于直接判断社会影响力或关系亲密程度。

### 3.3 用户关系和重要节点

当前系统可以：

- 查询指定用户；
- 查看一阶或局部关注关系；
- 展示关注关系方向；
- 按入度排序；
- 按出度排序；
- 按 PageRank 排序；
- 按用户资料中的粉丝数、关注数和推文总数排序；
- 查看用户详情、关系和推文摘要。

其中：

- 入度是当前数据集中指向该用户的有效关系数量；
- 出度是当前数据集中该用户指向其他用户的有效关系数量；
- 粉丝数和关注数来自用户资料字段；
- 入度、出度和账号资料字段的统计范围可能不同；
- PageRank 表示网络结构中的相对重要位置，不等于粉丝数或综合影响力。

### 3.4 推文互动分析

当前系统可以：

- 统计点赞、评论和转发数量；
- 计算总量、平均值、中位数和有效样本数；
- 统计零值和缺失值；
- 按推文展示互动排行；
- 按用户聚合互动结果；
- 展示互动数据的时间分布。

这些结果描述的是当前采集样本中的互动数量，不代表账号完整历史数据，也不代表内容传播的完整过程。

### 3.5 文本主题分析

当前系统可以：

- 对推文文本进行规范化；
- 进行关键词匹配；
- 计算词频和文档频率；
- 计算 TF-IDF；
- 回溯匹配关键词对应的推文；
- 展示主题相关用户；
- 将主题相关用户与真实关注关系进行联动。

主题分析用于说明“哪些文本内容与当前查询相关”，不用于判断用户立场、传播因果或社会影响力。

### 3.6 结果导出

当前系统支持将分析结果导出为：

- JSON；
- CSV；
- 可打印摘要。

后续更适合将导出按钮放在各分析模块右上角，使用户直接导出当前模块结果，而不是在页面底部统一选择导出范围。

## 4. 基于现有数据可以继续实现的功能

以下功能主要依赖用户 ID 和关注关系，现有数据具备实现基础。

### 4.1 全局关系网络图

可以将：

- 用户表示为节点；
- 关注关系表示为有向边；
- 入度较高的节点使用更大的尺寸；
- PageRank 较高的节点使用更明显的颜色；
- 点击节点查看用户详情；
- 支持缩放、拖拽和局部关系查看。

该图可以直观回答“谁和谁存在关系”“哪些用户处于网络中心”等问题。

### 4.2 社群发现

可以基于关系网络计算社群，将关系紧密的用户划分为不同群体。

页面可以展示：

- 社群数量；
- 每个社群的用户数；
- 每个社群的核心用户；
- 社群内部关系数量；
- 社群之间的关系数量；
- 社群模块度或其他划分质量指标。

可视化时可以使用淡色背景圈或淡色区域标识不同社群，但需要在界面中说明：

> 社群表示当前关系结构中的相对紧密群体，不等同于真实组织、社会身份或利益集团。

### 4.3 核心节点和桥接节点

可以进一步识别不同类型的节点：

- 社群内部连接较多的核心节点；
- 连接不同社群的桥接节点；
- 位于网络边缘的节点；
- PageRank 高但粉丝数不一定高的结构性节点。

桥接节点可以使用介数中心性、跨社群连接数等指标辅助识别。

### 4.4 网络连通性和结构特征

可以计算：

- 连通分量数量；
- 最大连通子图；
- 平均路径长度；
- 节点平均度；
- 聚类系数；
- 关系互惠性；
- 核心—边缘结构；
- 社群模块度。

这些指标可以帮助判断网络是集中型、分散型、分群型还是存在明显中心节点。

### 4.5 多指标综合查看

可以让用户同时比较：

- 入度；
- 出度；
- PageRank；
- 粉丝数；
- 关注数；
- 推文总数；
- 社群编号；
- 桥接程度。

但不建议直接将这些指标简单相加生成“综合影响力分数”，除非明确给出标准化方式、权重依据和验证结果。

## 5. 需要补充数据后才能实现的功能

以下功能不是完全不能做，而是当前数据字段不足，必须补充新的数据或时间维度。

### 5.1 真实互动网络

如果要分析“谁点赞了谁”“谁评论了谁”“谁转发了谁”，需要记录：

- 互动类型；
- 互动发起者 ID；
- 被互动对象 ID；
- 对应推文 ID；
- 互动时间。

当前数据只有点赞数、评论数和转发数等聚合数字，无法还原具体互动双方。

### 5.2 真实传播路径

如果要绘制内容传播路径，需要：

- 转发链路；
- 回复链路；
- 引用关系；
- 传播时间；
- 原始推文与衍生推文的对应关系。

没有这些字段，只能展示互动数量，不能声称展示了真实传播路线。

### 5.3 网络动态演化

如果要分析网络如何随时间变化，需要多个时间点的数据快照，例如：

- 不同日期的用户关系；
- 新增关注关系；
- 取消关注关系；
- 用户活跃变化；
- 社群合并或分裂过程。

当前数据主要是单一版本的静态网络，因此只能描述当前结构，不能可靠描述网络演化。

### 5.4 链路预测

如果要预测未来谁可能关注谁，需要：

- 历史关系变化；
- 用户互动记录；
- 多时间点网络；
- 用户属性和行为特征。

只有静态关系网络时，可以做算法演示，但不能验证预测准确率，也不能将结果当成可靠预测。

### 5.5 影响力变化和同伴效应

如果要判断某个用户是否影响了另一个用户，需要：

- 行为发生时间；
- 关系建立时间；
- 内容曝光或互动记录；
- 干预前后的行为变化；
- 对照组或实验数据。

仅凭关注关系、点赞数和评论数，不能得出“某个用户导致了另一个用户的行为变化”这一因果结论。

## 6. 当前不能可靠实现的功能

### 6.1 不能直接判断谁“真正有影响力”

粉丝数、入度、PageRank 和互动量分别反映不同方面：

- 粉丝数反映账号资料中的总体粉丝规模；
- 入度反映当前数据中记录到的被关注关系；
- PageRank 反映网络结构位置；
- 互动量反映当前采集样本中的互动数量。

它们都不能单独等同于真实社会影响力。

### 6.2 不能直接判断社群的真实身份

算法划分出的社群只能说明用户在关系网络中相对靠近，不能直接说明这些用户一定属于：

- 同一个组织；
- 同一个政治阵营；
- 同一个兴趣群体；
- 同一个利益集团。

如果要解释社群含义，还需要结合用户资料、文本内容和人工标注。

### 6.3 不能直接判断信息传播因果

当前数据不能证明：

- 某个用户引发了某条内容传播；
- 某条推文因为某个节点而获得互动；
- 某个社群导致了某个舆情结果。

这些结论需要传播链路、时间顺序和因果识别设计。

### 6.4 不能将静态结果表述为未来预测

当前模块适合描述历史和当前数据结构，不适合直接使用以下表述：

- 一定会成为核心用户；
- 一定会形成新的关系；
- 一定会引发传播；
- 一定会成为热门账号。

如果没有时间序列和验证集，应该使用“当前网络中”“在本数据集内”“历史样本显示”等限定表述。

## 7. 推荐的产品定位

当前社交网络分析模块最适合定位为：

> 基于真实用户关系数据的网络结构、社群划分和节点角色分析工具。

推荐的功能优先级如下：

### 第一优先级：关系网络可视化

- 节点—边关系图；
- 关系方向；
- 节点搜索；
- 点击节点查看详情；
- 局部网络展开。

### 第二优先级：社群发现

- 社群颜色；
- 社群背景圈；
- 社群规模；
- 社群核心节点；
- 社群间关系。

### 第三优先级：节点角色分析

- 核心节点；
- 桥接节点；
- 边缘节点；
- 入度、出度和 PageRank 对照。

### 第四优先级：更完整的网络结构指标

- 连通分量；
- 聚类系数；
- 平均路径长度；
- 互惠性；
- 模块度；
- 核心—边缘结构。

## 8. 面向用户的结果边界说明

建议在页面中保留以下说明性文字：

> 本模块基于当前数据集中记录的用户和关注关系进行网络结构分析。结果可以反映节点位置、社群结构和关系连接情况，但不等同于真实社会影响力、信息传播路径或因果关系。

对于推文互动部分，建议使用：

> 互动统计来自当前采集的推文样本。由于数据未完整记录互动双方和传播链路，互动数量不能直接还原信息传播过程。

对于社群发现部分，建议使用：

> 社群由网络结构算法划分，表示关系相对紧密的节点集合，不代表真实组织或群体身份。

对于用户上传数据，建议使用：

> 自定义数据集需要至少提供用户表和关系表。若希望进行推文互动或主题分析，还需要提供推文内容、作者 ID、时间和互动字段。系统会根据字段完整性提示可分析范围，不会使用缺失字段虚构结果。

## 9. 总结

当前模块已经具备社交网络分析的基础数据和计算能力，但目前展示内容偏向“数据统计、排序和质量说明”。

真正体现社交网络分析价值的下一步，应从单纯的排行榜扩展到：

```text
关系网络图
+ 社群发现
+ 核心与桥接节点
+ 网络结构指标
+ 明确的数据边界
```

基于现有用户和关注关系数据，可以可靠实现网络结构和社群分析；但真实传播路径、未来关系预测、社会影响因果和同伴效应分析，需要额外的互动对象、时间序列和实验数据，不能仅凭当前数据直接得出。
